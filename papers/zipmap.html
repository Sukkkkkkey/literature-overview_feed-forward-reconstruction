01 / MOTIVATION快速重建之后，能否留下可再次读取的场景？

批量几何模型通常输出每张输入图的点图和相机；完成后仍保留了昂贵或庞大的内部特征。ZipMap 希望一次处理中同时完成两件事：以线性随视图数扩展的成本恢复观测几何，并留下可查询新视角的紧凑场景状态。

贡献：帧内 local attention 与大块 TTT 交替的骨干，在 fast weights 中保存场景，并连接目标 raymap 查询。

原文依据：§1、§3 · 固定版本 PDF · 原文 HTML

02 / METHOD把全局交互写入每层快速权重

图像由 DINOv2 编码，加入 camera/register tokens。24 个骨干块交替进行帧内注意力与全局 large-chunk TTT；后者用所有输入视图的 token 一起更新 SwiGLU MLP 的 fast weights，再由查询读取。

W′ = Normalize(W − NS(∇WLKV))
oᵢ = Gate(fW′(qᵢ))

上式仅概括更新关系，省略论文逐 token 学习率和具体参数布局。NS 表示 Newton–Schulz 处理；动态学习率、权重归一化及输出门控共同稳定写入和读取。虚拟 K→V 目标不同于外层的三维重建 loss。

两类输入，两个作用

图像 tokens 提供新场景信息。目标相机 raymap 每像素包含 origin、direction 及二者叉积，共九维；它只查询已有 fast weights，输出目标视角 RGB、depth 与 confidence。观测视图另有相机、局部点图与深度读出。

为什么主模型是双向，仍可另做流式版本？

主方法在每层将所有输入视图一次性作为大块更新，因而每张图都能利用其他视图信息。流式版本则每次只用当前视图更新 fast weights；数据到达顺序和训练条件改变了。两者共享机制，但不是同一信息预算，论文将流式结果放在附录单列。

对固定维度 fast weights，单个目标 token 的读取不随输入图像数增长；整张目标图仍有自身 token 数与网络成本。首次场景编码时间和多次查询时间必须分开计入。

原文依据：§3.1–3.4；附录D.5 · 固定版本 PDF · 原文 HTML

03 / TRAINING先学几何，再扩展状态查询

使用相机、局部点图、depth 和局部平滑监督。训练先指定参考视图，再加入动态数据，最后移除参考图特权并采用相对/相似自由度的相机目标。输入图像的几何损失与目标视角 RGB/depth 查询损失分开，后者在查询微调阶段启用。

初始化复用 VGGT 的图像 encoder、帧内 attention 和部分全局投影；模型在 29 个公开数据集组成的混合数据上分阶段训练。不能把其全部结果解释为仅替换一层、无需外层训练的改造。

原文依据：§3.5；附录B.1–B.3 · 固定版本 PDF · 原文 HTML

05 / DISCUSSION查询能力与真实观测覆盖

本页分析fast weights 的容量与输入图数脱钩，但仍可能随场景复杂度饱和。新视图预测越远离观察覆盖，越依赖先验；输出几何与颜色一致也不证明未见部分真实。

研究延伸固定场景覆盖改变采样密度，固定视图数改变独立房间数量，再扫描 fast-weight 宽度与更新步数，能更清楚地区分冗余处理、优化充分性和容量限制。
