01 / MOTIVATION几千幅图像的全局关系，能否压进小网络？

VGGT 的多视推理依赖全局 attention，查询每个 token 时都要访问其他视图的 key/value。随着图像数增长，这种变量长度的场景表示带来二次交互成本。VGG-T³ 研究如何转换已有强骨干，将每层 KV 关系压缩为固定大小的 MLP。

目标主要是离线、无序集合的全局重建。保留双向信息聚合，使其与逐帧递归的 TTT3R、CUT3R 在信息预算上不同。

贡献：将预训练 VGGT 的全局 attention 线性化为 fast-weight 层，支持大集合分批/分布式推理，并演示同一场景状态上的图像定位。

原文依据：§1、§3 · 固定版本 PDF · 原文 HTML

02 / METHODUpdate 写入关联，Apply 读取几何上下文

每个全局层把输入投影成 Q/K/V。Update 用当前图像集合的 K→V 关系更新一个 SwiGLU MLP；Apply 将 Q 输入更新后的 MLP，得到替代全局 attention 的特征。最终层之后才由原预测头读出深度、相机等几何。

K,V → Update(W) → Wscene
Q → fWscene(Q) → 下一层 → 几何读出

直接替换为什么不够？

原 attention 的 QK LayerNorm 有可学习参数，论文发现它妨碍快速权重转换时的收敛，改用 L2 normalization。另一个问题是同一 token 经线性投影得到 K 和 V，关联目标可能过于简单；ShortConv2D 在图像网格上混合 V 的邻域，使目标还携带周围内容。

分批、分布式为什么可行？

在同一组 W 上，内层目标对全部 token 的梯度可写为各 mini-batch 梯度之和。可以逐批加载到 GPU，或在多 GPU 分别计算后同步更新。必须在共同参数点累积梯度；每批立即更新再处理下一批，是另一个顺序算法。

因此固定图像分辨率、内层步数和 MLP 容量时，写入/读取随图像数线性扩展。大场景可能需要更多内层更新以改善拟合，成本就还要乘更新步数。CPU offload 也转移了内存位置，未消除所有数据存储。

地图上的新图像定位

重建后冻结各层 fast weights，新图像只运行 Apply，不再更新场景参数；得到相对已建场景的相机与几何。这是图像定位接口，与 ZipMap 用已知目标相机 raymap 查询未见视角不同。

03 / TRAINING转换预训练模型，而不是从零学全部几何

以公开 VGGT 权重初始化，保留既有 encoder、帧内处理和几何读出，仅适配替换后的全局层。实现采用 SwiGLU fast-weight MLP、Muon 更新、点积形式的内层关联目标，以及 V 分支上的 3×3 ShortConv2D。

原文在与 VGGT 相近的数据组成上训练 100k steps，使用 8 张 A100-80GB。外层几何训练负责使内层记忆机制可被下游任务使用。测试阶段的更新只作用于这些场景 fast weights，不使用测试场景真实深度或位姿标签。

原文依据：§4 Implementation details；附录A · 固定版本 PDF · 原文 HTML

原文支持

预训练全局模型可以转成更可扩展的场景权重表示，大集合推理与查询得到明显效率优势。

不能推出

宽基线质量完全无损、固定容量可表达任意场景，或增加内层步数后仍有同样的速度比。

05 / DISCUSSION隐式地图的容量边界

原文边界论文明确指出与 softmax 的差距，尤其在宽基线输入下。固定 MLP 的表达能力与全量 token 交互之间仍有取舍。

本页分析观察 inner objective 持续改善，而几何误差停滞或变坏时，应考虑外层读出分布偏移；观察增加宽度有效而增加步数无效时，则更像容量瓶颈。两种问题需要不同扩展策略。
